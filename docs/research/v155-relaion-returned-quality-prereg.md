# V155 ReLAION-1M sparse returned-quality gate

**Decision:** does the V154 cached sparse route's 8.55× paired offline
CPU p95 advantage retain usable returned quality relative to the same
run's flat β=4 planner? This is the already-used ReLAION-1M
validation-1000 split. The V154 source, four-arm plan artifact and
input seal are frozen; no graph budget, page target, transport cap or
query choice changes.

The synthetic sparse V140-shaped raw plan is generated by
`python3 -m scripts.v155_relaion_returned_quality prepare` from the
closed V154 `science.jsonl` and V140 `relaion.raw.jsonl`. A full local
1,000-row conversion produced SHA-256
`1cfdacf4135b3dc3bfe93d9fd19a3b98f914b9a089e9f61107d89233a6ba8916`;
the worker checks this digest before scoring. Its flat plan is checked
field by field against V140 during conversion.

Use the authenticated complete V154 a0002 terminal, SHA-256
`09301ea5dfbb75aef49e7f34869903c15def2dfcd0eb787214f924fb191c5068`,
and its `science.jsonl`, SHA-256
`ab9bac04c32445a85928dd8978468b1c40d937da2f89960e71d8d21d132ea4d1`.
Use the V116 requests and sealed Rust router records, V140 raw β=4
plans, V114 SQ8 mirror manifest and sidecar, V70 SQ8 object, V36 source
parquet and GT100, and V63 layout, each authenticated by recorded
length and SHA-256. V142's complete returned-quality attempt is an
additional deterministic baseline audit, not a source of new
measurements.

Before opening GT, require every V154 flat page plan to equal the
corresponding V140 β=4 plan. Score 512 returned SQ8 IDs from each
flat and sparse physical range with the existing production Rust
bounded-range scorer. For flat, require exact ordered top-512 ID parity
with terminal-closed V142. Validate SQ8 source IDs against the V63
layout and V36 source IDs. Union the 512 Rust returned IDs with the
same V116 source-only 512 router nominees; rank exact source vectors
using V142's D768 normalization and (score, ID) tie rule, then seal
the ordered source top-100 and SQ8 top-100 IDs. Download GT100 only
after both arms' returned IDs and their hash seal have been uploaded
with conditional immutable S3 writes. Require the reduction and
postterminal verifier to match that seal. Recount all 1,000 hit rows
against GT after terminal closure, with planned bytes/GETs and
physical fetched-GT coverage.

The same-run flat result must reproduce V142's 99,607 exact-source
hits and 99,255 SQ8-only hits before judging sparse. Sparse passes
development quality only with at least 99,500 exact-source hits,
within 100 hits of same-run flat, p05 at least 98 hits, at most two
queries below 90, and no greater aggregate planned bytes or GETs.
Report paired wins/ties/losses, exact-source and SQ8 Recall@100,
physical coverage, p05/sub-90, per-query bytes/GETs, source-union
width, resource peaks and CPU phases. A failure means revise the
generic candidate discovery or recall/resource policy; do not tune
the used cohort to make its numbers pass. A pass permits reserved
held-out confirmation, not default freeze or live-S3 claims.

Run one committed, immutable source archive on one Causality Spot
instance. Monitor incomplete work only by terminal marker and
instance health. On interruption, sync the failed terminal, discard
the whole cell and restart under a new attempt ID. Authenticate all
terminal artifacts, independently recount them after closure, and
terminate compute immediately. Keep heavy execution off the devbox
while local swap pressure remains.
