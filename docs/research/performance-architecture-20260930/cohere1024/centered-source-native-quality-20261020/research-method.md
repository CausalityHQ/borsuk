# Research operating method

## Root-owned autoresearch loop

1. Maintain one generic-library product goal and one evidence ledger.
2. Identify the current measured bottleneck or recall-loss stage.
3. State one falsifiable hypothesis and one causal change. Write the smallest test capable of rejecting it.
4. Freeze inputs, comparator, source, quality and resource envelope before execution.
5. Run actual native correctness/recall admission, then a separate disposable SDK/CLI/cleanup canary before paid performance work.
6. Measure recall, per-query loss, p90/p95, cohort QPS, physical requests/bytes/retries, CPU, RSS and lifecycle cost.
7. Keep gains and useful Pareto candidates. Preserve valid negatives and INVALID executions distinctly.
8. Integrate only qualified coherent slices; choose the next useful iteration. A handoff is not product completion.

Prioritize reaching S3 Vectors first. Matched quality and full lifecycle economics determine the target. Turbopuffer official docs supply labeled references until a matched run exists.

## Short-lived contextless Devbox specialists

Use the installed devbox-plan-execute skill and live specialist_start schema. One fresh session per bounded iteration. Supply only task, exact source/inputs, relevant measured facts, constraints and acceptance checks. Do not pass root history, preferred verdict or an accumulated research persona.

Root retains scientific choices, experiments, source integration and infrastructure authority. Children get one owned worktree, one original sequential controller, bounded CPU/RAM/swap/tasks/time, explicit file scope, source cutoff and handoff deadline. No recursive specialists or duplicate consultation.

Verify actual brief consumption and exact-base checkout. Inspect committed diff, native results, source/ELF pins and remaining gaps. Close/archive at a safe terminal checkpoint. Do not leave children polling after handoff or carry them into the next research iteration.

## Simulator-style questions

For substantive choices, simulate relevant perspectives and turn disagreements into tests. These are prompts, not expert testimony:

| Perspective | Questions | Required evidence |
|---|---|---|
| ANN researcher | Where is exact-GT loss: router, coverage, local rank or quantization? What would falsify the proposed fix? | Stage attribution and native quality oracle |
| Storage engineer | How many causal waves, physical requests and bytes? Does merging change ranked population? | Trace conservation and authenticated ranges |
| Systems engineer | What survives cancellation, concurrent queries, generation swap and recovery? | Real barriers, drain/recovery tests, bounded capacity/model checks |
| Cost reviewer | Does saving GETs increase bytes/CPU/storage/maintenance enough to lose? | Versioned regional prices and measured lifecycle units |
| Skeptical customer | Is it generic, correct for nonunit vectors/tails/IDs, and operational without another maintenance instance? | Dimension/distribution falsifiers and lifecycle integration |
| Benchmark reviewer | Are corpus/query bytes, metric, k, filter, consistency, cache, clocks, retries and concurrency actually matched? | Frozen paired protocol and immutable source/service receipts |

Synthesize one testable decision; do not run a panel for trivial fixes. Verify consequential claims against source, official documentation or measurements.

## Source, execution and integration

All source/prep/build/test runs on the intended bounded EC2 lane. Keep local Devbox orchestration light. Spot by default, fixed guest and external shutdown, retained evidence, interrupted cells INVALID; no timeout-driven duplicate jobs.

Use one original job handle. Verify terminal PIDs/cgroup before mutations or replacement. Reuse unchanged fresh evidence. Require affected native execution, exact Clippy correctness/suspicious, real override-unset full test compilation and relevant release artifact pins. Full-suite pass claims require full-suite evidence.

Freeze dependency features/toolchain/flags as well as source for causal comparisons. Check original/current controls are actually rebuilt when sharing targets. Preserve operator identity and inherited missing Git objects; no history hydration just to commit owned files.

Fast-forward verified slices directly to origin/main, no PR or force push. Documentation does not prove product completion. Never rewrite historical thresholds after seeing outcomes.

## Clean-context continuity

A reset removes provider conversation only. It must not erase Git, evidence, instructions, goals or original job handles. First create a small restart handoff with:
- active objective and latest operator priorities;
- main/candidate refs and immutable evidence pointers;
- current unresolved falsifier and smallest next action;
- live child/job IDs, resource bounds and shutdowns;
- required safety/integration gates and unknowns.

Ask Devbox for the supported exact-instance route. No raw terminal keys, invented reset command or replacement agent to bypass controls. Prefer a terminal child/job boundary. The new context reads this method, the ledger and the small handoff, then verifies external state before acting. Do not reload the old transcript.
