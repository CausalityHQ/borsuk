## Safety argument (reviews reconciled)
Zero bytes are not an ownership proof (too strict for a launch-created volume, too weak for a reused one). Ownership = (1) the launcher's pre-publication API gate, (2) the create-only binding v2 + sha companion + SHA-pinned schema asset, (3) unique NVMe serial == binding volume id, exact size, (4) root backing disk excluded by device identity and its serial checked against the binding root volume, (5) all signature/partition/mount/swap/blkid checks unchanged, (6) mkfs without -F and under a finite timeout. The cmp becomes a RECORDED diagnostic: status 0 or 1 pass, anything else refuses. Disqualifiers on replay: root partition UUID/fstype/mount change, cmp status other than 0/1, any binding fact not re-derivable from the pinned raw API responses.
