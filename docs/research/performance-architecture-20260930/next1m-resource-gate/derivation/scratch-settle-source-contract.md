## Behaviour
settle(observe, volume, instance, clock, sleep, window=30, spacing=2, limit=12) observes ONLY the original scratch attachment, then the unchanged scratch_proof/binding/publication run on the settled body.
 * at most 12 observations inside a 30 s window; one `describe-volumes --volume-ids <scratch>` per observation; spacing sleep min(2, time left - 3); a new call starts only with >= 3 s left;
 * every call is clamped: subprocess timeout min(25, left) and the CLI read timeout min(15, int(left)); no unbounded sleep or wait;
 * the elapsed monotonic time is checked immediately AFTER each call and again immediately BEFORE the success return: an attached body that arrives after 30 s is refused (exactly 30.000 s is accepted; no success after it);
 * `attaching` is never final; the only continuing state is attaching. Immediate refusal (no sleep, no retry) of: AWS error status (rc != 0), empty/oversize(>64 KiB)/non-bytes/malformed body, missing/empty/duplicated Volumes or Attachments, foreign volume or instance, device != /dev/sdf, and any attachment state other than attaching/attached (detaching, detached, busy, missing);
 * evidence: each observation is its own file set describe-scratch-volume-NN.{command.json,stdout,stderr,exit} (NN = 01..12, each stdout <= 64 KiB); a TIMED-OUT observation (subprocess.TimeoutExpired, only calls that pass keep=True, i.e. the observations) first writes its capped partial stdout/stderr and `exit` = TIMEOUT under the same name, then propagates (no retry); RunInstances and every other call behave exactly as before;
 * the settled body is the exact final file: the launcher re-reads it and requires equality, binds describe_volumes_sha256 to its sha256, and exposes its basename in launch-root-result.json key `scratch_volume_final_evidence` (e.g. describe-scratch-volume-02.stdout). The root's replay pin ec2.volume must name that file; ec2.instance_running stays describe-original.stdout.
Any refusal, timeout or exception leaves no binding and falls into the existing cleanup (one RunInstances, one claim, emergency terminate when the watcher did not start).
Resource: at most 30 s of extra launcher wall time and 12 DescribeVolumes calls (a0004 needed a second look; typical 1-3); no extra compute or storage.
