# Cold measurement counter boundary
Inspected committed source c3e52c8bbf0fcc985c0a8a06d2abeec5d7442d38: sq8_s3_range.rs and check_cohere_native_baseline.rs; no runtime execution.
NativeTransportStats.attempts is a transport invocation count, explicitly not proof that each request reached the wire or S3. It records methods, statuses, transport/stream failures, consumed payload bytes and dropped error bodies. Both object_store retries and reqwest transport retries are disabled; real HTTP fault fixtures test absence of hidden retries. Those fixtures do not turn counters into billed-request evidence.
Unread/cancelled bodies, headers, TLS/kernel wire bytes and billed requests/bytes remain unknown. Terminal output keeps these fields null. Keep that distinction in the paired performance table and total-dollar accounting; do not label consumed bytes as physical network or billed bytes.
Query wall time surrounds native generation search including its awaited reads. Generation open/publication are separate lifecycle phases and must be reported separately or included explicitly in an end-to-end boundary. Diagnostic counter sampling outside the query window does not establish total application latency.
The baseline explicitly emits physical_s3_measured=false and external_gate_required=true, including when the backend is S3. A source configuration or successful panel alone cannot override that claim. The frozen cold campaign needs its existing external request/network instrumentation and cache-state protocol plus actual terminal evidence before asserting physical cold performance.
Application-cache disabled is controllable; provider-side coldness is not proven by fresh process or namespace alone. Disclose provider cache state as uncontrolled unless independently evidenced. Preserve historical benchmark scope unchanged.
