# Separate read and compute limits

Prospective Rust library intervention; not implemented or measured. Keep selected width64 and all old protocols frozen. Configure request count, active body bytes, queued authentication bytes, authentication workers, scoring workers, and active queries independently. Share process limits across readers/generations; per-query plans still reserve their total retained payload and trace/scratch.

- Download permits cover network work; byte permits cover receiving and queued bodies. Release these permits when ownership moves to an authenticated outcome, whose retained bytes remain charged to the query. Holding all permits until the ordered batch completes would deadlock when the batch exceeds the active-byte cap.
- Before any GET, validate every range and refuse an impossible weighted permit request. A range larger than the byte window needs an explicit larger-range policy or a different cover; it must never wait for permits that cannot exist.
- CPU admission is distinct from I/O. A bounded verification worker or cooperative verification can preserve event-loop responsiveness on one CPU; multi-core throughput requires a separately admitted CPU envelope. Do not assume either gain from the existing aggregate CPU figures.
- Preserve plan-index ordering of successful results and first errors. Drain all submitted work after failure. Cancellation must retain byte/worker charges until work actually ends; no detached uncharged compute or generation references.
- Score work may parallelize independent rows while preserving each row accumulation order and final score/ID ordering. The failed portable8-row batch is retained; do not repeat it as a SIMD success.
- Fast native falsifier: actual loopback HTTP transport with held bodies, byte-window saturation, oversized-range pre-I/O refusal, ordered dual failures, queued refill, cancellation and zero remaining workers/body charges. Assert exact results, traces and charges against the current reader.
- Causal transport screen: unchanged source/query/plan/CPU envelope, one changed scheduling policy; capture existing range stamps plus TCP/ENA counters in the same units. S3/TCP/event-loop causes remain hypotheses until these observations discriminate them.
- Then run actual-input admission and staging before a frozen paired cold cell. Keep numerical parity; measure p90/p95/p99,QPS,RSS,physical requests/bytes and costs. No new defaults or vendor win until the evidence passes.

## Source inspection of selected main0b85

The selected reader already uses indexed buffer_unordered outcomes and restores plan order after all futures complete (sq8_s3_range.rs around685). Do not reintroduce the older ordered-buffer scheduling. Each future currently collects its whole planned range then calls PageAuthority.verify_payload synchronously around912, on the same async polling lane; request slots therefore cover both receive and authentication. The first tier change must separate these ownership stages while preserving existing indexed error selection and full drain. Total planned payload is already admitted before GETs and completed bodies remain retained, so an active-byte window supplements rather than replaces that reservation. This inspection establishes the coupling, not that authentication causes the measured network tail.

Authentication ownership constraint: PageAuthority currently owns a Vec of per-page SHA256 digests and verification borrows it. Offloading each range with a copied whole authority would introduce unmodeled per-range digest amplification. Prefer a shared pinned authority or an explicitly charged range-local proof; any spawned worker must own its payload/proof and remain charged and joined through cancellation. A cooperative page verifier is a separate one-core candidate that can retain borrows and yield between pages, but does not claim CPU parallelism. Keep these alternatives distinct in the first causal falsifier.
