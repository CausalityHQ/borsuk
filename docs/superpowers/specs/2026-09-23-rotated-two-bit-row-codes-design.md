# Rotated two-bit row codes: one frozen 100k falsifier

## Decision

The terminal-closed page-centered group attempt at source `fd3b14ba` passed its exact grouped arm (98.515% mean and 92% p05 GT100) but failed its page-centered PQ48 arm (96.787% and 85%). Exact scoring on the *same rows* recovered 1,728 GT100 hits and never worsened a query. This isolates row-score fidelity, not group locality, as the next 100k blocker. The result and source/terminal identities are in `docs/research/algorithm-first-page-layout-ledger.md`.

Test one substantially different, fixed representation: source-centered, orthogonally rotated two-bit scalar codes with an individually fitted scale. It uses four times the bits per row of PQ48, within the measured group-read budget. The primary score is squared distance to the code reconstruction; a norm-corrected score using a stored exact source norm is a mandatory paired diagnostic on the same bits. The experiment asks whether this scalar code closes the measured gap while keeping the 32-GET, 16-MiB code wave. V85's sign-Hadamard preconditioner worsened PQ16, but did not test scalar two-bit codes. This is a bounded feasibility gate, not an isolated rotation/compression comparison or a product format freeze.

## Frozen inputs and construction

Reuse the authenticated ReLAION-100k source, 480-KiB two-means membership, geometric tree, 1,000 development queries and GT100 from the closed group attempt. Keep all 166 page identities and the exact first-32-distinct four-page group plan per query. The membership/layout seed remains `20260921`; use a separate fixed **rotation** seed `20260923`. No query, truth or prior result is available to construction. Train a single global mean from all 100,000 source vectors in source-ordinal order with float64 NumPy reduction, cast once to stored little-endian float32, and use that stored mean for both source and query subtraction in float64. For coordinate `j` in `0..767`, the sign is positive when the low bit of byte zero of `SHA256(b"borsuk-sq2-sign-v1" || little_endian_u32(rotation_seed) || little_endian_u32(j))` is zero and negative otherwise. Apply these signs **before** three independent 256-coordinate Walsh-Hadamard butterflies in float64 and divide each block by 16. This transform is orthogonal before storage rounding; it preserves squared norms and distances before quantization.

For each rotated source row, fit one nonnegative scalar `s` for four symmetric levels `{-3,-1,+1,+3}`. Initialize float64 `s = mean(abs(y))/1.6`, then run exactly eight assignment/least-squares updates in float64: assign magnitude level 3 only when `abs(y)>2s`, otherwise 1; assign nonnegative values positive; set `s = sum(c*y)/sum(c*c)`. Store the **eighth assignment and its fitted scale**, with no ninth reassignment. Specify the zero-vector case as `s=0` and all level-1 positive codes. Map `-3,-1,+1,+3` to symbols `0,1,2,3`, pack four two-bit symbols per byte in increasing dimension order, low bits first: 192 code bytes per 768D row. Store little-endian float32 `s` and float32 exact squared norm of the source-centered row: 200 bytes per row. Store the rounded float32 global mean once in the sealed format. Version this as a new incompatible experimental code format; no old reader or migration layer.

Each immutable S3 group contains a little-endian u32 page count, one little-endian u32 row count per consecutive page, then the 200-byte records in physical membership order. Bind source/membership/tree hashes, mean, separate layout/rotation seeds, all row order, group coordinates and each group SHA-256 in a source-only canonical seal. The validator reconstructs the source-only mean, transform, assignments and bytes independently. Reject any unexpected source or artifact identity.

## Query scoring and paired controls

Transform each query after subtracting the stored source mean. For each row in the first 32 distinct groups, use the stored float32 scale `s` and unpacked integer levels `c`. The **primary reconstructed-distance** score is `||q-mean||² + s²*sum(c*c) - 2*s*dot(rotated_q,c)`; the mandatory **norm-corrected diagnostic** replaces `s²*sum(c*c)` with the stored float32 exact source-centered norm squared. Accumulate each term in float64, cast each final score once to float32, and rank by `(score, source_ordinal)`. The least-squares residual is approximately orthogonal to the quantized ray, not to the query; norm correction adds a row-dependent reconstruction-error penalty and could hurt nearest-row ranking, as V103's different PQ norm correction did. Only the preregistered reconstructed-distance arm can advance this cell. If it fails but the norm-corrected diagnostic passes, classify an estimator mismatch and require a separately frozen confirmation before promotion rather than killing the encoded bits.

Compare against exact source-vector squared distances on precisely the same grouped candidate rows, then use the unchanged top-100-row and page nomination rule under 32 pages/16 MiB. Authenticate and join the closed page-centered group evidence by query ordinal: the new exact pages and hits must match its terminal-closed exact arm for **every** query, as well as its candidate group ordinal plan. Join closed global PQ48 and residual PQ48+PQ24 GT100 controls from that same evidence. An independent validator directly unpacks scalar codes, recomputes query transforms and exact/primary/diagnostic page nomination for every query, checks all prior joins, and reproduces all aggregates. Test 768D equal-distance tie behavior and corrupt/short/reordered group reads before launch.

## Read and resource bounds

The closed page-centered evidence fixes 1,000 query group plans and per-page row counts. Replacing its 48-byte records with 200-byte records and removing unused page means projects a maximum of **15,423,240 bytes** (77,113 rows plus 640 header bytes) across 32 group GETs, leaving 1,353,976 bytes below 16 MiB. Assert this bound from the new manifest before launch. Construct and validate source rows in batches of at most 4,096; decode and score grouped candidates in batches of at most 2,048. Do not retain a full float64 source matrix or full float64 candidate decode. The worker must perform actual authenticated S3 Range GETs, disable SDK retries for measurement reads, count successful GETs and bytes, and fail on any short/corrupt response. Cap code wave at 32 GETs/16,777,216 bytes, planned final data wave at 32 pages/16,777,216 encoded bytes, and every construct/evaluate/validate worker phase below 3 GiB RSS with zero swap.

At 100M, 200-byte row records imply a 20-GB S3 code plane, not resident RAM. The global mean is 3,072 resident bytes; fixed rotation needs only a seed. A compact geometric router must omit unused full-dimensional page centroids and prove two-generation resident allocation below 3 GiB before promotion. This 100k cell does not measure native final-page GETs, SQ8 serving recall/latency, generation overlap or competitor parity.

## Decision rule

On all 1,000 frozen queries, require mean GT100 >=97.5%, nearest-rank p05 GT100 >=90%, and GT10 page containment >=96%, plus both wave caps and independent replay. A new exact-arm disagreement with the closed group evidence is a noneligible implementation/provenance failure, not new science about the group shortlist. If the exact arm matches and primary scoring misses any quality gate, kill reconstructed-distance scoring for this representation; if the diagnostic also misses, kill the encoded two-bit representation. Do not sweep widths, seeds, scales or group sizes. If the primary passes, label it only `quality-advance-memory-pending`. The next gate is a 1M code-group locality and native serving cell from a separately frozen source plus a measured centroid-free two-generation resident worksheet. An interrupted Spot attempt is noneligible and restarted in a fresh immutable prefix only.
